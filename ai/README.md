# ИИ-модуль КТК ЭЛОУ-АВТ

Автономный MVP ИИ-модуля для сценария `MVP-SC-01` — развивающийся отказ
сырьевого насоса Н-1А. Модуль не импортирует код `backend` и пока не подключен
к WebSocket.

## Что реализовано

- подготовленные объяснимые подсказки для обучающего режима;
- отключение подсказок в контрольном режиме;
- дедупликация подсказок в пределах сессии;
- шаблонный итоговый разбор результата и ошибок;
- явное указание метода и источников в `provenance`.

В live-режиме LLM не вызывается на каждом кадре телеметрии. Правила проверяют
только значимые состояния и действия, поэтому результат быстрый,
детерминированный и не требует сети. Генеративную модель в дальнейшем разумно
вызывать один раз после сессии для стилистической персонализации уже
проверенного отчета.

Все пороги, правильный диагноз, последовательность переключения и шкала оценки
в текущем MVP являются **учебными допущениями** (`A-02`, `A-17`, `A-18`), а не
реальными производственными инструкциями или уставками.

## Структура

- `contracts.py` — независимые входные и выходные контракты;
- `hint_engine.py` — выбор одной приоритетной live-подсказки;
- `report_builder.py` — итоговый детерминированный разбор;
- `data/hints.json` — тексты и приоритеты подготовленных подсказок;
- `data/report_rules.json` — расшифровки ошибок и рекомендации;
- `examples/demo.py` — пример запуска;
- `tests/` — автономные тесты.

## Вход live-подсказок

`HintContext.from_payload()` принимает снимок телеметрии и накопленный журнал
действий. Достаточный минимальный снимок:

```json
{
  "sessionId": "f3656f3b-3b2c-44e5-9cb8-46b50ad6f715",
  "timing": {"elapsedMs": 12000},
  "components": [
    {
      "componentId": "eq-n1a",
      "status": "warning",
      "operatingState": "running",
      "parameters": [
        {
          "parameterId": "temperature",
          "valuePercent": 68,
          "status": "warning"
        }
      ]
    }
  ]
}
```

`training`/`control` — это режим сессии, а `timing.mode` в телеметрии означает
режим хода времени (`live`). Поэтому режим обучения нужно передать отдельным
аргументом:

```python
context = HintContext.from_payload(snapshot, actions, mode="training")
```

В контрольном режиме используется `mode="control"`, и движок всегда возвращает
`None`.

Действия передаются отдельным списком в формате текущего контракта сценария:

```json
[
  {"actionType": "open_equipment_card", "targetId": "eq-n1a", "parameters": {}},
  {"actionType": "view_signal", "targetId": "PRA351", "parameters": {}}
]
```

## Выход live-подсказки

```json
{
  "type": "ai.hint",
  "sessionId": "f3656f3b-3b2c-44e5-9cb8-46b50ad6f715",
  "virtualTimeMs": 12000,
  "hintId": "inspect-n1a",
  "level": "warning",
  "title": "Проверьте Н-1А",
  "message": "Статус Н-1А изменился. Откройте карточку оборудования и изучите доступные диагностические признаки.",
  "evidence": [
    {"kind": "component", "refId": "eq-n1a", "fact": "Статус Н-1А: warning"}
  ],
  "provenance": {
    "method": "deterministic_rule",
    "llmUsed": false,
    "sourceRefs": ["A-02", "учебное допущение"]
  }
}
```

За один вызов возвращается одна наиболее приоритетная новая подсказка или
`None`. Повторная отправка одной подсказки в той же сессии блокируется.

## Итоговый отчет

`SessionReportBuilder.build()` принимает результат сценария, журнал действий и
выданные подсказки. Возвращаются:

- краткий итог;
- сильные стороны;
- ошибки с кодами и объяснениями;
- рекомендации;
- число действий и подсказок;
- происхождение анализа (`llmUsed: false`).

Поддерживается фактический ответ `GET /api/v1/sessions/{sessionId}/result` с
полями `outcome`, `diagnosis`, `stabilization`, `consequenceControl`,
`timeliness` и `errorCodes`.

## Запуск

Из корня репозитория:

```bash
python3 -m ai.examples.demo
python3 -m unittest discover -s ai/tests -v
```

Сторонние Python-зависимости для прототипа не нужны.

## Последующая интеграция

После согласования контракта backend сможет:

1. передавать в `HintEngine` очередной снимок и журнал действий только при
   значимом событии;
2. отправлять результат `Hint.to_payload()` во frontend через существующий
   WebSocket;
3. после завершения передавать результат оценки в `SessionReportBuilder`;
4. сохранять итоговый разбор вместе с отчетом сессии.

Эта ветка интеграцию не выполняет и файлы `backend/`/`frontend/` не изменяет.
