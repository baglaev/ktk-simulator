# ИИ-модуль КТК ЭЛОУ-АВТ

Автономный пакет ИИ-модуля для сценария `MVP-SC-01` — развивающийся отказ
сырьевого насоса Н-1А. Пакет не импортирует код `backend`: backend использует
его RAG через отдельный адаптер, а подготовленные live-подсказки отправляет
собственным WebSocket-сервисом без сетевых вызовов.

## Что реализовано

- подготовленные объяснимые подсказки для обучающего режима;
- отключение подсказок в контрольном режиме;
- дедупликация подсказок в пределах сессии;
- шаблонный итоговый разбор результата и ошибок;
- детерминированный разбор последовательности и виртуального времени действий;
- необязательное улучшение итогового отчета через OpenAI-compatible API;
- минимальный RAG по проектным документам с локальным поиском и ссылками;
- явное указание метода и источников в `provenance`.

В live-режиме LLM не вызывается на каждом кадре телеметрии. Правила проверяют
только значимые состояния и действия, поэтому результат быстрый,
детерминированный и не требует сети. Генеративную модель в дальнейшем разумно
вызывать один раз после сессии для персонализации уже проверенного отчета. Такой
вызов реализован как необязательный второй этап; при любой ошибке остается
исходный детерминированный отчет.

Все пороги, правильный диагноз, последовательность переключения и шкала оценки
в текущем MVP являются **учебными допущениями** (`A-02`, `A-17`, `A-18`), а не
реальными производственными инструкциями или уставками.

## Структура

- `contracts.py` — независимые входные и выходные контракты;
- `hint_engine.py` — выбор одной приоритетной live-подсказки;
- `report_builder.py` — итоговый детерминированный разбор;
- `action_analysis.py` — этапы, последовательность и виртуальное время действий;
- `openai_compatible.py` — клиент совместимого `/chat/completions` API;
- `llm_report_enhancer.py` — безопасное улучшение итогового отчета;
- `rag_documents.py` — извлечение документов и локальный JSON-индекс;
- `rag_retriever.py` — локальный BM25-поиск без векторной БД;
- `rag_assistant.py` — ответ через LLM только по найденным фрагментам;
- `data/hints.json` — тексты и приоритеты подготовленных подсказок;
- `data/report_rules.json` — расшифровки ошибок и рекомендации;
- `examples/demo.py` — пример запуска;
- `examples/build_rag_index.py` — построение RAG-индекса;
- `examples/rag_question.py` — один вопрос к базе знаний;
- `tests/` — автономные тесты.

## Вход live-подсказок

`HintContext.from_payload()` принимает снимок телеметрии и накопленный журнал
действий. Достаточный минимальный снимок:

```json
{
  "sessionId": "f3656f3b-3b2c-44e5-9cb8-46b50ad6f715",
  "timing": {"elapsedMs": 12000},
  "components": [
    {
      "componentId": "eq-n1a",
      "status": "warning",
      "operatingState": "running",
      "parameters": [
        {
          "parameterId": "temperature",
          "value": 76,
          "unit": "°C",
          "status": "warning"
        }
      ]
    }
  ]
}
```

`training`/`control` — это режим сессии, а `timing.mode` в телеметрии означает
режим хода времени (`live`). Поэтому режим обучения нужно передать отдельным
аргументом:

```python
context = HintContext.from_payload(snapshot, actions, mode="training")
```

В контрольном режиме используется `mode="control"`, и движок всегда возвращает
`None`.

Действия передаются отдельным списком в формате текущего контракта сценария:

```json
[
  {"actionType": "open_equipment_card", "targetId": "eq-n1a", "parameters": {}},
  {"actionType": "view_signal", "targetId": "PRA351", "parameters": {}}
]
```

## Выход live-подсказки

```json
{
  "type": "ai.hint",
  "sessionId": "f3656f3b-3b2c-44e5-9cb8-46b50ad6f715",
  "virtualTimeMs": 12000,
  "hintId": "inspect-n1a",
  "level": "warning",
  "title": "Проверьте Н-1А",
  "message": "Статус Н-1А изменился. Откройте карточку оборудования и изучите доступные диагностические признаки.",
  "evidence": [
    {"kind": "component", "refId": "eq-n1a", "fact": "Статус Н-1А: warning"}
  ],
  "provenance": {
    "method": "deterministic_rule",
    "llmUsed": false,
    "sourceRefs": ["A-02", "учебное допущение"]
  }
}
```

За один вызов возвращается одна наиболее приоритетная новая подсказка или
`None`. Повторная отправка одной подсказки в той же сессии блокируется.

## Итоговый отчет

`SessionReportBuilder.build()` принимает результат сценария, журнал действий и
выданные подсказки. Возвращаются:

- краткий итог;
- сильные стороны;
- ошибки с кодами и объяснениями;
- рекомендации;
- число действий и подсказок;
- происхождение анализа (`llmUsed: false`).

### Разбор действий

Поле `actionAnalysis` рассчитывается программно до вызова нейросети:

- `stages` — обнаружение, диагностика, переключение, контроль восстановления и
  завершение со статусами `success`, `warning`, `alert`;
- `timing` — момент первой реакции, корректного диагноза, завершения
  переключения и последней проверки восстановления;
- `sequence` — соблюдение порядка диагноза и учебного переключения;
- `timeline` — обезличенная последовательность принятых действий;
- `strengths` — подтвержденные сильные стороны;
- `focusAreas` — конкретные этапы для повторной отработки.

Значения `warningAtMs` и границы сценарных окон относятся только к виртуальному
времени `MVP-SC-01`. Это учебные допущения `A-02`, `A-17`, `A-18`, а не
производственные нормативы.

Поддерживается фактический ответ `GET /api/v1/sessions/{sessionId}/result` с
полями `outcome`, `diagnosis`, `stabilization`, `consequenceControl`,
`timeliness` и `errorCodes`.

Из корня репозитория:

## OpenRouter

По умолчанию используется бесплатный маршрутизатор `openrouter/free`. Он
выбирает одну из доступных бесплатных моделей, поэтому конкретная модель может
меняться между запросами. Фактически выбранная модель записывается в
`provenance.resolvedModel`.

1. Создайте API-ключ в OpenRouter.
2. Создайте локальный файл `ai/.env` из примера:

```bash
cp ai/.env.example ai/.env
```

3. Впишите ключ в `OPENROUTER_API_KEY`. Файл `.env` исключен из Git.
4. Загрузите переменные и выполните один тестовый отчет:

```bash
set -a
source ai/.env
set +a
python3 -m ai.examples.openrouter_report
```

Проверка успешного вызова:

```json
{
  "method": "deterministic_plus_llm",
  "llmAttempted": true,
  "llmUsed": true,
  "requestedModel": "openrouter/free",
  "resolvedModel": "фактически выбранная модель"
}
```

Если ключ отсутствует, превышен лимит, провайдер недоступен или модель вернула
невалидный JSON, программа не теряет отчет. Она возвращает детерминированную
версию с `llmUsed: false`, `llmStatus: "fallback"` и безопасным описанием
причины в `llmErrorMessage`.

Настройки:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `AI_LLM_ENABLED` | включить внешний вызов | включается при наличии ключа |
| `AI_LLM_BASE_URL` | базовый URL совместимого API | `https://openrouter.ai/api/v1` |
| `AI_LLM_MODEL` | модель или роутер | `openrouter/free` |
| `OPENROUTER_API_KEY` | секретный ключ | отсутствует |
| `AI_LLM_TIMEOUT_SECONDS` | таймаут одного отчета | `45` |
| `AI_LLM_MAX_TOKENS` | ограничение ответа | `1200` |
| `AI_LLM_TEMPERATURE` | вариативность текста | `0.2` |
| `AI_LLM_DATA_COLLECTION` | политика маршрутизации OpenRouter | `deny` |

Ключ никогда не передается во frontend и не записывается в отчет. Во внешний
API не отправляются `sessionId`, `traineeId` и `instructorId`. Нейросеть
получает только обезличенный отчет и уже рассчитанное поле `actionAnalysis`; она
не определяет правильность или время действий самостоятельно.

Для OpenRouter запрос по умолчанию содержит
`provider.data_collection: "deny"`. При этом внешнему бесплатному провайдеру
все равно передается содержимое запроса для обработки, поэтому нельзя отправлять
секретные сведения, персональные данные и реальные производственные данные.

Актуальные ссылки:

- [OpenRouter: использование OpenAI SDK и совместимого API](https://openrouter.ai/docs/guides/community/openai-sdk);
- [OpenRouter: бесплатный маршрутизатор](https://openrouter.ai/docs/guides/routing/routers/free-router);
- [OpenRouter: политики провайдеров](https://openrouter.ai/docs/guides/privacy/provider-logging).

## Минимальный RAG по документам

RAG отвечает на вопросы только по найденным фрагментам проектных документов.
Документы индексируются локально и не отправляются целиком во внешний API. В
OpenRouter передаются вопрос и не более четырех релевантных фрагментов.

Поддерживаются форматы:

- TXT, Markdown и Mermaid;
- DOCX без дополнительных Python-библиотек;
- PDF с текстовым слоем через `pdftotext` из пакета Poppler.

Изображения и сканы без текстового слоя в MVP не распознаются. Файлы, которые не
удалось сопоставить с картой происхождения, по умолчанию не индексируются.
Производный файл `ai/data/rag_index.json` исключен из Git.

### 1. Построить индекс

На macOS при отсутствии `pdftotext` установите Poppler:

```bash
brew install poppler
```

Из корня репозитория выполните:

```bash
python3 -m ai.examples.build_rag_index \
  --source-dir "/полный/путь/КТК_ЭЛОУ_АВТ_пакет_для_промта"
```

Команда создаст `ai/data/rag_index.json` и выведет количество документов,
фрагментов и пропущенных файлов. Индекс нужно перестроить после изменения
исходных документов.

Путь можно сохранить в локальном `ai/.env`:

```bash
AI_RAG_DOCUMENTS_DIR="/полный/путь/КТК_ЭЛОУ_АВТ_пакет_для_промта"
AI_RAG_INDEX_PATH=ai/data/rag_index.json
AI_RAG_TOP_K=4
AI_RAG_MAX_CONTEXT_CHARS=8000
```

После этого загрузите переменные перед построением индекса:

```bash
set -a
source ai/.env
set +a
python3 -m ai.examples.build_rag_index
```

### 2. Задать вопрос

Загрузите переменные OpenRouter и выполните:

```bash
set -a
source ai/.env
set +a
python3 -m ai.examples.rag_question "Какую роль выполняет насос Н-1А?"
```

Бесплатный маршрутизатор может выбрать провайдера, который отклонит конкретный
запрос. В этом случае fallback сохранит найденные источники. Для воспроизводимой
демонстрации можно указать конкретную доступную модель, например проверенную на
этом прототипе:

```bash
AI_LLM_MODEL=google/gemma-4-26b-a4b-it:free \
  python3 -m ai.examples.rag_question "Какую роль выполняет насос Н-1А?"
```

Основной контракт ответа:

```json
{
  "type": "ai.rag.answer",
  "question": "Какую роль выполняет насос Н-1А?",
  "answer": "Ответ со ссылками [S1] и [S2].",
  "insufficientEvidence": false,
  "sources": [
    {
      "label": "S1",
      "sourceRef": "03_технологические_источники/03_насосное_оборудование.pdf#1-page-1",
      "filePath": "03_технологические_источники/03_насосное_оборудование.pdf",
      "sourceType": "technology_source",
      "sourceTypeLabel": "технологический источник",
      "locator": "page-1",
      "score": 1.0,
      "excerpt": "Фрагмент найденного текста"
    }
  ],
  "provenance": {
    "method": "local_retrieval_plus_llm",
    "llmUsed": true,
    "sourceRefs": [
      "03_технологические_источники/03_насосное_оборудование.pdf#1-page-1"
    ]
  }
}
```

Модель получает только локальные метки `[S1]`, `[S2]`. Ссылка на несуществующий
фрагмент считается ошибкой, после чего возвращается безопасный fallback со
списком найденных источников. Если бесплатная модель выбрала существующий
источник, но не поставила его метку в текст, приложение детерминированно добавит
эту метку в конец ответа. Если релевантных фрагментов нет, LLM не вызывается и
возвращается `insufficientEvidence: true`.

RAG не рассчитывает физическую модель, не оценивает правильность действий и не
управляет оборудованием. Его зона ответственности — поиск подтвержденного
контекста и объяснимая формулировка ответа.

## Интеграция с backend

Backend уже выполняет следующие функции:

1. отправляет подготовленные подсказки сообщением `scenario.hint` только в
   режиме `training`;
2. сохраняет время реально показанных подсказок;
3. строит и сохраняет детерминированный SCR-05 после завершения;
4. вызывает RAG через `POST /api/v1/sessions/{sessionId}/assistant/question`
   только для завершённой сессии.

Самостоятельные классы `HintEngine`, `SessionReportBuilder` и примеры сохранены
для изолированной разработки и тестирования AI-логики. Frontend пакет AI не
импортирует и секреты провайдера не получает.
