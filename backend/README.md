# Backend КТК

## Реализованный стек

- Python
- FastAPI
- Pydantic
- WebSocket
- pytest

SQLAlchemy, Alembic и PostgreSQL запланированы для этапа персистентного
хранения. Текущий MVP хранит активные сессии в памяти одного процесса.

## Запуск каркаса

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
uvicorn app.main:app --reload
```

Проверка: <http://127.0.0.1:8000/health>

По умолчанию разрешены запросы frontend с `http://localhost:5173` и
`http://127.0.0.1:5173`. Настройки находятся в `.env.example`.

## API сценариев

- `GET /api/v1/scenarios` - каталог доступных сценариев.
- `GET /api/v1/scenarios/MVP-SC-01/model-definition` - оборудование, связи,
  сигналы, источники и учебные допущения сценария Н-1А.
- `GET /docs` - интерактивная документация OpenAPI.

## Учебная модель Н-1А

Детерминированная модель находится в `app/simulation`. Траектории сигналов
заданы в `app/scenarios/data/n1a_model_profile.json`. Все коэффициенты,
временные точки и модельные значения имеют ссылки на учебные допущения.

Модель реализует `initialize`, `step`, `apply_action` и `get_snapshot`.
Одинаковая последовательность шагов и действий формирует одинаковый результат.

## API учебных сессий

- `POST /api/v1/sessions` - создать сессию.
- `POST /api/v1/sessions/{id}/start` - запустить модель.
- `POST /api/v1/sessions/{id}/pause` - приостановить сессию.
- `POST /api/v1/sessions/{id}/resume` - продолжить сессию.
- `POST /api/v1/sessions/{id}/complete` - завершить сессию.
- `GET /api/v1/sessions/{id}` - получить состояние сессии.
- `GET /api/v1/sessions/{id}/snapshot` - получить полный снимок модели.
- `POST /api/v1/sessions/{id}/actions` - передать учебное действие.
- `POST /api/v1/sessions/{id}/advance` - продвинуть время сценария;
  служебный детерминированный шаг для тестов и отладки.

После запуска сессии backend автоматически продвигает модель и публикует
телеметрию. Frontend не должен регулярно вызывать `/advance`.

## WebSocket телеметрии

- `WS /ws/v1/sessions/{id}` - поток состояния запущенной учебной сессии.
- Первое сообщение — полный `telemetry.snapshot` для инициализации фронта.
- Следующие сообщения — `telemetry.update` с тем же полным упорядоченным
  списком восьми экранных компонентов.
- Параметры находятся внутри `components[].parameters`, передаются через
  `valuePercent`; отдельного массива `signals` в WebSocket-контракте нет.
- Статусы компонентов и параметров унифицированы: `success`, `warning`,
  `alert`.
- `sequenceNo` позволяет упорядочивать сообщения и отбрасывать устаревшие,
  `stateVersion` используется для согласования действий, а `timing` содержит
  live-время, общую длительность, остаток и процент прохождения.

Неизвестная сессия закрывается с кодом `4404`, ещё не запущенная — `4409`.
Browser Origin, отсутствующий в списке разрешённых, закрывается с кодом `4403`.
Рассылка текущего MVP работает внутри одного процесса FastAPI. Redis/Kafka для
этого этапа не требуются; внешний брокер понадобится при нескольких worker или
экземплярах backend.

## Live-время сценария

Цикл модели запускается и останавливается вместе с FastAPI. Он продвигает
только сессии со статусом `running`; `pause` замораживает время сценария,
`resume` продолжает расчёт, `complete` исключает сессию из цикла. Достижение
`totalDurationMs` автоматически завершает сессию.

- `KTK_SIMULATION_TICK_INTERVAL_MS` — интервал между расчётами в реальном
  времени.
- `KTK_SIMULATION_AUTO_RUN` — включение автоматического цикла.

Интервал по умолчанию 1000 мс означает одну секунду сценария за одну реальную
секунду. Общая длительность MVP — 120 000 мс. Длительность и траектории
являются **учебными допущениями**, а не производственными нормативами.

Контракт передачи frontend: [FRONTEND_INTEGRATION.md](FRONTEND_INTEGRATION.md).

Активные сессии пока хранятся в памяти одного процесса и теряются при
перезапуске backend. Запуск нескольких worker потребует общего хранилища
состояния; это будет реализовано на следующем инфраструктурном этапе.
